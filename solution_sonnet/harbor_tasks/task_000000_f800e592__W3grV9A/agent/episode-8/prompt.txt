PROBLEM:
--------
The gen_report.py script was generating report filenames with incorrect timestamps.
When run from cron (which may have TZ=UTC or no TZ set), the script would use
UTC time instead of the configured Asia/Tokyo timezone, resulting in timestamps
like 00:00:00 instead of 09:00:00 (9 hour difference).

ROOT CAUSE:
-----------
The script was reading /etc/timezone and setting os.environ['TZ'], but Python's
datetime module doesn't automatically pick up TZ environment changes after the
process starts. Simply setting os.environ['TZ'] is not enough.

SOLUTION:
---------
Added two critical changes to gen_report.py:
1. Import the 'time' module
2. Call time.tzset() immediately after setting os.environ['TZ']

This forces Python to reload timezone information and apply the new TZ setting.
