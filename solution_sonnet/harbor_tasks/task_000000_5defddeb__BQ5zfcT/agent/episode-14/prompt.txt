INCREMENTAL BACKUP FIX - May 6, 2026
=====================================

PROBLEM:
Incremental backups were producing corrupt/incomplete archives due to a race condition.
The script was updating the timestamp reference BEFORE tar finished writing the archive.

ROOT CAUSE:
In incremental.sh, the tar command was backgrounded with '&', then the timestamp was
immediately updated with 'date +%s > $TIMESTAMP_FILE', and only AFTER that did the
script wait for tar to complete with 'wait $TAR_PID'.

This caused the reference time to be updated before tar finished reading all files,
leading to:
- Missed files in subsequent backups
- Inconsistent state tracking
- Archives that appeared complete but were missing data

SOLUTION:
Swapped the order of operations in the incremental branch:
  OLD ORDER:
    1. Start tar in background
    2. Update timestamp  <-- WRONG: happens before tar finishes
    3. Wait for tar

  NEW ORDER:
    1. Start tar in background
    2. Wait for tar       <-- CORRECT: wait first
    3. Update timestamp  <-- Only update after tar completes

VERIFICATION:
- Fixed script now produces small incremental archives containing only changed files
- Archives extract successfully without corruption
- Multiple sequential incrementals work correctly
