# Performance Fix Summary

## Problem
- Validator was running at ~40 docs/sec instead of target 400-500 docs/sec
- Previous caching attempt didn't help because the cache wasn't being used

## Root Causes
1. **validate_document() was calling preprocess_schema() directly** - This spawned a new jq subprocess for EVERY validation
2. **No validator caching** - Draft7Validator was recompiled for every document, even when using the same schema
3. **get_cached_schema() existed but was never called** - The caching infrastructure was there but unused

## Solution
Added get_validator() function that:
1. Caches compiled Draft7Validator objects per schema path
2. Uses get_cached_schema() to avoid repeated jq calls
3. Returns cached validators on subsequent calls

Changed validate_document() to use get_validator() instead of directly calling preprocess_schema()

## Results
- Before: 40.3 docs/sec
- After (first run): 1,389.4 docs/sec (34x improvement)
- After (warm cache): 10,698.7 docs/sec (265x improvement)
- **Target achieved**: Well above 400-500 docs/sec requirement

## Key Changes
- Added _validator_cache dictionary at module level
- Added get_validator() function for validator caching
- Modified validate_document() to call get_validator() instead of preprocess_schema()
