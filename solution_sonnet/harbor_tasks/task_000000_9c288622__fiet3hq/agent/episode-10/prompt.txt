# Timezone Bug Fix Summary

## Problem
The meeting reminder application was sending reminders at incorrect times, off by exactly one hour for meetings falling between 2am-3am local time (Europe/Berli
n). This was particularly problematic for the Monday 2:30am maintenance window reminder.

## Root Cause
The bug was in the `convert_to_berlin()` function in `/home/user/scheduler/app.py`.

### Buggy Code (line 28):
```python
def convert_to_berlin(utc_time_str):
    utc_dt = datetime.strptime(utc_time_str, '%Y-%m-%dT%H:%M:%S')
    berlin_dt = BERLIN_TZ.localize(utc_dt)  # BUG!
    return berlin_dt
```

**Problem**: `BERLIN_TZ.localize(utc_dt)` treats the naive datetime as if it's already in Berlin timezone, rather than converting FROM UTC TO Berlin.

### Fixed Code:
```python
def convert_to_berlin(utc_time_str):
    utc_dt = datetime.strptime(utc_time_str, '%Y-%m-%dT%H:%M:%S')
    utc_dt_aware = UTC_TZ.localize(utc_dt)  # Make it UTC-aware
    berlin_dt = utc_dt_aware.astimezone(BERLIN_TZ)  # Convert to Berlin
    return berlin_dt
```

**Solution**: First make the datetime UTC-aware, then convert it to Berlin timezone using `astimezone()`.

## Impact
- **Before fix**: UTC times were incorrectly treated as Berlin times
- **Time offset**: 1-2 hours depending on DST status
- **Most problematic**: DST transition dates (like March 31, 2024) where 2am-3am is skipped

### Example (Maintenance Window):
- UTC Time: 2024-03-31 01:30:00
- **Buggy result**: 2024-03-31 01:30:00 CET (wrong!)
- **Correct result**: 2024-03-31 03:30:00 CEST (correct!)
- **Difference**: 2 hours off
