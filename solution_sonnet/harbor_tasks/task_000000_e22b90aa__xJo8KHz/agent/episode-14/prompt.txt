PROBLEM:
- 40 out of 200 rows in merged.parquet had NaT (Not a Time) values in the recorded_at column
- All NaT values were from sensor_c data

ROOT CAUSE:
- transform.py had a hardcoded datetime format: "%Y-%m-%d %H:%M:%S"
- sensor_c.csv used European date format: "DD/MM/YYYY HH:MM:SS" (e.g., 25/03/2024 14:30:00)
- Other sensor CSVs used ISO format: "YYYY-MM-DD HH:MM:SS" (e.g., 2024-03-01 08:00:00)
- The hardcoded format couldn't parse DD/MM/YYYY dates, causing them to become NaT
- errors='coerce' silently converted unparseable dates to NaT instead of raising errors

SOLUTION:
- Modified parse_timestamps() function in transform.py
- Changed from: format="%Y-%m-%d %H:%M:%S"
- Changed to: format='mixed'
- This allows pandas (v2.0+) to automatically detect and parse multiple date formats
