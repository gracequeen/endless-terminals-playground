# MLService Deployment Fix

## Problem
The service was failing with "No module named 'tokenizers'" when run with `python -m mlservice` from within the `/home/user/mlservice` directory.

## Root Cause
When running `python -m mlservice` from inside the mlservice directory itself, Python's module resolution cannot properly import the mlservice package. The pack
age needs to be run from its parent directory (`/home/user`).

## Solution
Use the provided `start_service.sh` script instead of running `python -m mlservice` directly.

### For Production Deployment
Replace:
```bash
cd /home/user/mlservice
source .venv/bin/activate
python -m mlservice
```

With:
```bash
cd /home/user/mlservice
./start_service.sh
```

Or simply:
```bash
/home/user/mlservice/start_service.sh
```

The script handles venv activation and ensures the service runs from the correct directory.

## Verification
The service now successfully imports tokenizers and all other dependencies.
