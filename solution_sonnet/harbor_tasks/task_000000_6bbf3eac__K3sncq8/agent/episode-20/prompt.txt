# ETL Pipeline Makefile Fixes

## Issues Fixed

The Makefile had 4 critical bugs that caused:
- Rebuilding everything on every run (broken incremental builds)
- Segfaults and hangs with parallel builds (-j4)
- Missing dependencies causing incorrect builds

## Applied Fixes

### Fix #1: Added .SECONDEXPANSION directive
**Problem**: The pattern rule `clean/%.csv: data/%.csv` used `$$@` in the recipe without `.SECONDEXPANSION`, causing it to be treated as literal text instead of
 the target filename.

**Solution**: Added `.SECONDEXPANSION:` directive and changed recipe to use `$@` correctly.

### Fix #2: Fixed wildcard evaluation timing
**Problem**: `joined.csv: $(wildcard clean/*.csv)` evaluated at Makefile parse time. After first run when clean/ was empty, this evaluated to nothing, making jo
ined.csv have no dependencies.

**Solution**: Changed to `joined.csv: $(CLEAN_TARGETS) clean/manifest.txt` which uses the computed CLEAN_TARGETS variable that's always correct.

### Fix #3: Added manifest.txt dependencies
**Problem**: `clean/manifest.txt` had no dependencies, causing race conditions with -j4 where join.py could run before all clean files were ready.

**Solution**: Made `clean/manifest.txt: $(CLEAN_TARGETS)` so manifest is only created after all clean files exist.

### Fix #4: Added config/params.yaml dependency
**Problem**: `summary.csv` was missing `config/params.yaml` as a dependency, even though summarize.py reads this file.

**Solution**: Changed to `summary.csv: joined.csv config/params.yaml`

- ✓ No segfaults or hangs
