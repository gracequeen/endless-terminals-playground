PROBLEM ANALYSIS:
================

The intermittent "gzip: stdin: not in gzip format" errors were caused by
locale-dependent glob expansion in restore.sh.

ROOT CAUSE:
-----------
The .bashrc file contains a locale rotation mechanism that alternates
LC_COLLATE between 'C' and 'en_US.UTF-8' on each shell invocation.

The original restore.sh used:
  cat "$CHUNKS_DIR"/chunk_* | gunzip | tar xf - -C "$OUTPUT_DIR"

Glob expansion (chunk_*) order depends on LC_COLLATE:
- LC_COLLATE=C: ASCII ordering (uppercase before lowercase)
- LC_COLLATE=en_US.UTF-8: Case-insensitive ordering

When chunks are concatenated in the wrong order, the gzip stream is
corrupted, causing gunzip to fail.

SOLUTION:
---------
Fixed restore.sh to use explicit sorting:
  find "$CHUNKS_DIR" -name 'chunk_*' -type f | sort | xargs cat | gunzip | tar xf - -C "$OUTPUT_DIR"

The 'sort' command uses consistent ordering regardless of LC_COLLATE,
ensuring chunks are always concatenated in the correct sequence.

VERIFICATION:
-------------
Tested with both LC_COLLATE=C and LC_COLLATE=en_US.UTF-8:
- 10/10 restore operations successful
- Restored content matches original perfectly
- No more intermittent failures
