> # Git Hooks Security System
>
> ## Problem Identified
>
> A commit (5def323) by jenkins-bot contained a world-readable private key file (secrets/deploy.key with mode 644) that bypassed the pre-commit hook. Investigat
ion revealed the commit was made using `git commit --no-verify` (or `-n` flag), which bypasses pre-commit and commit-msg hooks.
>
> ## Root Cause
>
> The `--no-verify` flag allows users to bypass client-side git hooks, including:
> - pre-commit
> - commit-msg
> - pre-applypatch
>
> This is a known Git feature that can be exploited (intentionally or accidentally) to bypass security checks.
>
> ## Hardened Solution
>
> Implemented a multi-layer defense system that cannot be fully bypassed:
>
> ### Layer 1: pre-commit hook (existing)
> - **Location**: `.git/hooks/pre-commit`
> - **When it runs**: Before commit is created
> - **Can be bypassed**: Yes, with `--no-verify`
> - **Purpose**: First line of defense for normal commits
> - **Checks**: Staged files matching `*.pem` or `*.key` for world-readable permissions (644+)
>
> ### Layer 2: post-commit hook (NEW)
> - **Location**: `.git/hooks/post-commit`
> - **When it runs**: Immediately after commit is created
> - **Can be bypassed**: NO - always runs after any commit
> - **Purpose**: Catches commits made with `--no-verify`
> - **Action**: Alerts user immediately with instructions to fix
> - **Checks**: Files in the just-created commit for insecure permissions
>
> ### Layer 3: pre-push hook (NEW)
> - **Location**: `.git/hooks/pre-push`
> - **When it runs**: Before pushing to remote
> - **Can be bypassed**: Yes, with `--no-verify`, but provides additional checkpoint
> - **Purpose**: Final check before code leaves local repository
> - **Checks**: All `*.key` and `*.pem` files in working tree for insecure permissions
>
> ### Layer 4: pre-receive hook (NEW)
> - **Location**: `.git/hooks/pre-receive`
> - **When it runs**: On the server/remote when receiving a push
> - **Can be bypassed**: NO - server-side enforcement
> - **Purpose**: Ultimate enforcement point that cannot be bypassed by client
> - **Checks**: All files being pushed for insecure key permissions
> - **Note**: Only effective when pushing to a remote with this hook installed
>
> ## What Gets Checked
>
> - **File patterns**: `*.pem`, `*.key`
> - **Permission threshold**: 644 or looser (world-readable or group-readable)
> - **Required permissions**: 600 (owner read/write only) or 400 (owner read-only)
>
> ## How This Prevents Future Incidents
>
> 1. **Normal commits**: Blocked by pre-commit hook
> 2. **Commits with --no-verify**: Caught by post-commit hook immediately
> 3. **Before pushing**: Blocked by pre-push hook
> 4. **Server-side**: Blocked by pre-receive hook (when pushing to remote)
