> ## Problem
> The distributed feature extraction pipeline was producing incorrect output:
> - Only 12k rows instead of 50k (missing data)
> - Invalid tf-idf scores > 1.0 (mathematically impossible)
> - No errors or crashes (silent data corruption)
>
> ## Root Causes Identified
>
> ### 1. **Incorrect Vocabulary Management (CRITICAL)**
> Each worker was calling `vectorizer.fit_transform()` on individual chunks:
> ```python
> # WRONG - each chunk gets its own vocabulary
> vectorizer = TfidfVectorizer(max_features=100)
> tfidf_matrix = vectorizer.fit_transform(texts)  # Fits on chunk only!
> ```
>
> **Why this caused invalid scores:**
> - TF-IDF requires a unified vocabulary across ALL documents
> - Each chunk built its own vocabulary with different terms
> - IDF (inverse document frequency) was calculated only within each chunk
> - This produced invalid scores and incompatible feature columns
>
> ### 2. **Column Misalignment**
> Workers returned DataFrames with different column names (different vocabularies):
> - Worker 1 chunk: columns ['apple', 'banana', 'cherry', ...]
> - Worker 2 chunk: columns ['dog', 'elephant', 'fox', ...]
> - Coordinator's `pd.concat()` created union of all columns, filling missing values
> - Result: sparse, misaligned data with wrong dimensions
>
> ### 3. **Message Loss at Startup**
> Coordinator sent chunks immediately after binding sockets:
> ```python
> sender.bind("tcp://127.0.0.1:5557")
> # Immediately sends chunks - workers not connected yet!
> for chunk in chunks:
>     sender.send(chunk)
> ```
> ZeroMQ PUSH sockets can drop messages if no PULL sockets are connected.
>
> ### 4. **Poor Result Tracking**
> Coordinator used a list instead of dict for results:
> ```python
> results = []  # Can't detect missing chunks
> results.append(result_df)  # No chunk ID tracking
> ```
> Timeout-based completion meant lost chunks went undetected.
>
> ## Fixes Applied
>
> ### Fix 1: Unified Vocabulary (coordinator.py)
