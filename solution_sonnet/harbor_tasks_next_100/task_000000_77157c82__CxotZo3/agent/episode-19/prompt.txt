> # Log Filter Bug Fix Summary
>
> ## Problem
> Payment service ERROR logs were being dropped (not appearing in errors.log) while auth-service and inventory-service ERROR logs were processed correctly.
>
> ## Root Cause
> The `classify_line()` function in filter.py had an overly broad check for "structured" logs:
>
> ```python
> if 'T' in line[:25] and ':' in line[:25]:
>     return 'structured'
> ```
>
> This check was intended to identify structured/JSON logs but incorrectly matched ISO 8601 timestamps like `2024-01-15T08:48:40+00:00`.
>
> ## Why Only Payment Service Was Affected
> - **payment-svc**: Uses ISO 8601 timestamps: `2024-01-15T08:48:40+00:00 [ERROR] ...`
> - **auth-service**: Uses space-separated timestamps: `[ERROR] 2024-01-15 08:09:25 ...`
> - **inventory-service**: Uses space-separated timestamps: `[ERROR] 2024-01-15 08:30:16 ...`
>
> Payment-svc logs were misclassified as "structured" and routed to structured.log instead of being processed for severity-based routing to errors.log.
>
> ## Solution
> Modified `classify_line()` to only identify actual JSON logs:
>
> ```python
> def classify_line(line):
>     # Check for actual JSON only
>     stripped = line.strip()
>     if stripped.startswith('{') and stripped.endswith('}'):
>         return 'structured'
>     return 'plaintext'
> ```
>
> ## Results
> - Before fix: 0 payment-svc ERROR logs in errors.log
> - After fix: 76 payment-svc ERROR logs correctly routed to errors.log
> - Other services: Still working correctly (23 auth-service, 28 inventory-service)
> - Structured logs: Still properly captured (5 JSON logs from metrics-collector)
>

> - `/home/user/logpipe/filter.py` - Fixed classify_line() function
