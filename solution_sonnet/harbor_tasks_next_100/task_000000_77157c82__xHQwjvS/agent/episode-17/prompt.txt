# Log Filter Bug Fix Summary

## Problem
- 40% of ERROR logs from payment-svc were being dropped from errors.log
- They were appearing in raw.log but not in output/errors.log
- Other services (auth-service, inventory-service) were working fine

## Root Cause
The `classify_line()` function in filter.py had a flawed detection logic:
```python
if 'T' in line[:25] and ':' in line[:25]:
    return 'structured'
```

This was intended to detect structured/JSON logs, but it incorrectly matched:
- Payment-svc logs: `2024-01-15T08:48:40+00:00 [ERROR] service=payment-svc ...`
  (ISO 8601 timestamp with 'T' and ':' in first 25 chars)

While NOT matching:
- Auth/inventory logs: `[ERROR] 2024-01-15 08:30:16 service=auth-service ...`
  (No 'T' in timestamp format)

Result: Payment-svc ERROR logs were routed to structured.log instead of errors.log

## Solution
Simplified classify_line() to only detect actual JSON:
```python
def classify_line(line):
    stripped = line.strip()
    if stripped.startswith('{') and stripped.endswith('}'):
        return 'structured'
    return 'plaintext'
```

## Verification
- Before fix: 76 payment-svc ERROR logs in raw.log, 0 in errors.log (in structured.log instead)
- After fix: 76 payment-svc ERROR logs in raw.log, 76 in errors.log
- Total ERROR logs: 127/127 correctly routed (100% capture rate)
